# Executive Summary — Reviews

**Date:** 2026-07-06 · **Status:** Approved (documentation only) · **Full spec:** `TECH-SPEC.md`

The Lamina platform gains a single, **polymorphic** reviews & ratings system that attaches to any reviewable target — products, entries, custom types, pages, posts — via a `targetType`/`targetId` pair, mirroring the existing `block_sets.ownerType`/`ownerId` convention so it scales with custom types without a migration per type.

**Decisions (locked):** login-gated reviewers (`getViewer()` via `person_session`); per-target-type config with defaults — moderation **post** by default, verified gate **optional** by default; v1 surfaces are a drop-in block, review-request emails, REST API v1, and a Swift app (**not** auto-inject into templates).

**How it works:** a `computeVerified` step determines at submit time whether the reviewer transacted with / is entitled to the target — products via `orders`+`orderItems`, content via `resolveEntitlement` — and stores a `verified` badge (FTC-compliant, conversion-positive). Aggregates (`average`, `count`, distribution) are cached per target and recomputed synchronously on every status change. `Schema.org` JSON-LD is emitted for rich snippets. One review per person per target (unique index); one owner reply per review (Udemy-style).

**Scope:** five tables in `src/modules/reviews/` (schema already committed and wired into the schema barrel; `"review"` already in the activity enum), a module mirroring `commerce/`, a `reviews` block, admin moderation queue + per-target settings, the full `/api/v1/reviews` route set, and a Swift companion app. Migrations are generated by `npm run db:generate` (drizzle-kit), not hand-written.

**Deliberately deferred (no-migration upgrade paths):** weighted/decayed aggregation, ML moderation, course-completion verification, a real email driver, half-stars, multi-reply threading. Each is a documented open question, not a blocker.
