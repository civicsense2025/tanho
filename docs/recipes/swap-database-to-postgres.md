# Swap the database to Postgres

The default is libSQL (Turso/file), but the data layer is Drizzle, which
speaks Postgres, MySQL, and SQLite with one query API. Queries survive a
swap; only the driver and migrations change.

## Steps

1. **Install the driver**: `npm install pg` (and remove `@libsql/client` if
   you like).
2. **Change the client** in `src/lib/db/client.ts` to Drizzle's
   `node-postgres` (or `postgres-js`) driver, reading `DATABASE_URL`.
3. **Change the dialect** in `drizzle.config.ts` from `turso` to
   `postgresql`.
4. **Regenerate migrations**: delete `drizzle/` and run
   `npm run db:generate` against the Postgres dialect, then
   `npm run db:migrate`.
5. **Seed and test**: `npm run seed`, then run the app and the suite.

## What to watch for

- **Column types**: the schemas use SQLite-friendly types (integer unix-ms
  timestamps, `text({ mode: "json" })`). These map cleanly to Postgres
  (`bigint`, `jsonb`) but review the generated migration.
- **Booleans**: SQLite stores them as integers; Postgres has a real boolean.
  Drizzle handles the mapping, but check any raw comparisons.
- **`onConflictDoNothing`/upserts**: supported on both, syntax generated by
  Drizzle.

Because all reads/writes go through `src/modules/*/queries.ts` and
`actions.ts` using the Drizzle query builder (never raw SQL), no feature
code changes. See [../architecture/adapters.md](../architecture/adapters.md).

## The same pattern applies to storage, email, payments

Those are adapter interfaces too — swap the impl behind the interface, wire
it in the surface's `index.ts`, done.
